## Q1. What are the foundational and most-cited grammar-based fuzzers?

### Takeaway
Grammar-based generation goes back to Purdom's 1972 sentence generator. The modern line runs through Csmith (PLDI 2011), grammar-based whitebox fuzzing (PLDI 2008), LangFuzz (USENIX Security 2012), Skyfire (S&P 2017), Grammarinator (A-TEST 2018), Nautilus (NDSS 2019), Superion (ICSE 2019) and Gramatron (ISSTA 2021). All of these target program-like inputs such as JavaScript, C, XML or SQL. None of them targets natural-language prompts.

### Cited Findings (annotated bibliography)

**Classics / foundations**
- **Purdom, P.** (1972). "A sentence generator for testing parsers." *BIT Numerical Mathematics* 12, 1972. DOI: 10.1007/BF01932308 [CR]. This is the earliest systematic grammar-driven test generator: it derives short sentences that use every production at least once. It is the historical ancestor of the "cover every expansion" goal that our coverage-guided prompt grammar uses. — [Crossref/DOI](https://doi.org/10.1007/bf01932308). Note: Crossref also lists a second DOI with the same title, 10.1007/BF01932975, which is likely an erratum or duplicate. Cite 10.1007/BF01932308.
- **Lämmel, R., Schulte, W.** (2006). "Controllable Combinatorial Coverage in Grammar-Based Testing." In *Testing of Communicating Systems (TestCom 2006)*, LNCS. DOI: 10.1007/11754008_2 [CR]. It formalizes control over the combinatorial explosion of grammar-based test generation through coverage criteria and depth limits. This is directly relevant to bounding the size of our prompt space. — [Crossref/DOI](https://doi.org/10.1007/11754008_2). Crossref reports the LNCS series. The TestCom venue name is from memory and was not confirmed on the record.
- **Godefroid, P., Kiezun, A., Levin, M. Y.** (2008). "Grammar-based whitebox fuzzing." *Proc. 29th ACM SIGPLAN Conf. on Programming Language Design and Implementation (PLDI '08)*. DOI: 10.1145/1375581.1375607 [CR]. It combines a grammar with symbolic execution so that generated inputs pass the parser and reach deeper code. Its contrast with our black-box setting is that a chatbot's internals cannot be symbolically executed. — [Crossref/DOI](https://doi.org/10.1145/1375581.1375607). The same paper also appeared in *ACM SIGPLAN Notices* 43(6), DOI 10.1145/1379022.1375607.
- **Hoffman, D. M., Ly-Gagnon, D., Strooper, P., Wang, H.-Y.** (2010). "Grammar-based test generation with YouGen." *Software: Practice and Experience*. DOI: 10.1002/spe.1017 [CR]. A grammar-based test generator with tags that control combinatorial coverage of derivations. It is an early tool precedent for annotating grammars to steer generation. — [Crossref/DOI](https://doi.org/10.1002/spe.1017)
- **Yang, X., Chen, Y., Eide, E., Regehr, J.** (2011). "Finding and understanding bugs in C compilers." *Proc. 32nd ACM SIGPLAN Conf. on Programming Language Design and Implementation (PLDI '11)*. DOI: 10.1145/1993498.1993532 [CR]. This is Csmith: it randomly generates valid C programs and finds compiler bugs by **differential testing** across compilers. It is the closest classic precedent for our design, which combines grammar-generated inputs with a differential oracle across models. — [Crossref/DOI](https://doi.org/10.1145/1993498.1993532). Also reprinted in *SIGPLAN Notices* 46(6), DOI 10.1145/1993316.1993532.

**Modern grammar-based fuzzers (2012–2021)**
- **Holler, C., Herzig, K., Zeller, A.** (2012). "Fuzzing with Code Fragments." *21st USENIX Security Symposium (USENIX Security '12)*, Bellevue, WA, pp. 445–458. URL: https://www.usenix.org/conference/usenixsecurity12/technical-sessions/presentation/holler (no DOI) [WS]. LangFuzz uses a language grammar to parse sample code into fragments and recombine them into new test programs. It reported 105 new vulnerabilities in Mozilla's JavaScript engine in three months and 18 crash defects in PHP. It is the canonical grammar-based fuzzer and shows that grammar validity plus variation finds deep bugs. — [USENIX page](https://www.usenix.org/conference/usenixsecurity12/technical-sessions/presentation/holler); [Saarland PDF](https://www.st.cs.uni-saarland.de/publications/files/holler-usenix-2012.pdf). Note: some secondary listings give pp. 38–48. Use the USENIX pages, 445–458.
- **Wang, J., Chen, B., Wei, L., Liu, Y.** (2017). "Skyfire: Data-Driven Seed Generation for Fuzzing." *2017 IEEE Symposium on Security and Privacy (S&P)*. DOI: 10.1109/SP.2017.23 [CR]. It learns a probabilistic context-sensitive grammar from a corpus and generates seeds that favor low-probability productions. This is a probabilistic analogue of our "prefer rarely or never-used expansions" policy. — [Crossref/DOI](https://doi.org/10.1109/sp.2017.23)
- **Hodován, R., Kiss, Á., Gyimóthy, T.** (2018). "Grammarinator: a grammar-based open source fuzzer." *Proc. 9th ACM SIGSOFT Int. Workshop on Automating TEST Case Design, Selection, and Evaluation (A-TEST 2018)*, pp. 45–48. DOI: 10.1145/3278186.3278193 [CR]. An open-source generator that builds test generators from ANTLR v4 grammars. It is a practical tool baseline for grammar-driven generation that could also take a prompt grammar. — [Crossref/DOI](https://doi.org/10.1145/3278186.3278193)
- **Aschermann, C., Frassetto, T., Holz, T., Jauernig, P., Sadeghi, A.-R., Teuchert, D.** (2019). "NAUTILUS: Fishing for Deep Bugs with Grammars." *Network and Distributed System Security Symposium (NDSS 2019)*. DOI: 10.14722/ndss.2019.23412 [CR]. It combines grammar-based generation and tree mutation with code-coverage feedback, without needing seed corpora. This is the main precedent for *coverage-guided* grammar fuzzing. It uses code coverage as feedback, whereas we use grammar coverage. — [Crossref/DOI](https://doi.org/10.14722/ndss.2019.23412)
- **Wang, J., Chen, B., Wei, L., Liu, Y.** (2019). "Superion: Grammar-Aware Greybox Fuzzing." *2019 IEEE/ACM 41st International Conference on Software Engineering (ICSE)*. DOI: 10.1109/ICSE.2019.00081 [CR]. It extends AFL with grammar-aware, tree-based mutation and trimming. It shows that grammar awareness improves coverage-guided greybox fuzzing of structured inputs. — [Crossref/DOI](https://doi.org/10.1109/icse.2019.00081)
- **Eberlein, M., Noller, Y., Vogel, T., Grunske, L.** (2020). "Evolutionary Grammar-Based Fuzzing." In *Search-Based Software Engineering (SSBSE 2020)*, LNCS. DOI: 10.1007/978-3-030-59762-7_8 [CR]. It evolves grammar-generated inputs toward a fitness goal using evolutionary search. This is an alternative guidance strategy to the deterministic coverage preference we use. — [Crossref/DOI](https://doi.org/10.1007/978-3-030-59762-7_8). Crossref gives the LNCS series. The SSBSE venue name was not on the record.
- **Srivastava, P., Payer, M.** (2021). "Gramatron: effective grammar-aware fuzzing." *Proc. 30th ACM SIGSOFT Int. Symposium on Software Testing and Analysis (ISSTA 2021)*, pp. 244–256. DOI: 10.1145/3460319.3464814 [CR]. It restructures grammars into automata (grammar automatons) to make aggressive mutation of grammar-valid inputs efficient. It is the state of the art in grammar-aware mutation and a performance reference point. — [Crossref/DOI](https://doi.org/10.1145/3460319.3464814)
- **Veldkamp, L., Olsthoorn, M., Panichella, A.** (2023). "Grammar-Based Evolutionary Fuzzing for JSON-RPC APIs." *2023 IEEE/ACM Int. Workshop on Search-Based and Fuzz Testing (SBFT)*. DOI: 10.1109/SBFT59156.2023.00026 [CR]. It applies grammar-based fuzzing to a service API rather than a parser. This is the closest precedent for using grammars to test a remote service endpoint, as with querying a hosted chatbot. — [Crossref/DOI](https://doi.org/10.1109/sbft59156.2023.00026)

**Learning or mining grammars (context)**
- **Godefroid, P., Peleg, H., Singh, R.** (2017). "Learn&Fuzz: Machine learning for input fuzzing." *2017 32nd IEEE/ACM Int. Conf. on Automated Software Engineering (ASE)*. DOI: 10.1109/ASE.2017.8115618 [CR]. It learns a generative model of input structure (PDF objects) with neural networks instead of a hand-written grammar. This is the learned alternative to our hand-written prompt grammar. — [Crossref/DOI](https://doi.org/10.1109/ase.2017.8115618)
- **Höschele, M., Zeller, A.** (2016). "Mining input grammars from dynamic taints." *Proc. 31st IEEE/ACM Int. Conf. on Automated Software Engineering (ASE 2016)*. DOI: 10.1145/2970276.2970321 [CR]. Together with **Gopinath, R., Mathis, B., Zeller, A.** (2020), "Mining input grammars from dynamic control flow," *ESEC/FSE 2020*, DOI: 10.1145/3368089.3409679 [CR], these works infer grammars automatically from program behavior. They are relevant as future work, since a chatbot has no parser to mine, which is why we write the grammar by hand. — [Crossref/DOI](https://doi.org/10.1145/2970276.2970321); [Crossref/DOI](https://doi.org/10.1145/3368089.3409679)

### Inferences
- Csmith is the best single precedent for a "grammar generation + differential oracle" study. LangFuzz and Nautilus are the canonical precedents for grammar-based and coverage-guided grammar fuzzing.
- Every fuzzer in this list targets formal languages with a parser and crash or sanitizer oracles. Applying the same technique to natural-language prompts, with behavioral divergence as the oracle, is a clear point of novelty for our study.

## Q2. What work defines or evaluates grammar coverage / k-path coverage as guidance or adequacy criterion?

### Takeaway
Grammar (expansion) coverage as a generation goal goes back to Purdom (1972) and Lämmel & Schulte (2006). Its modern formulation is **k-path coverage** (Havrikov & Zeller, ASE 2019; extended in TOSEM 2022), which shows that covering input structure correlates with code coverage and raises it. *The Fuzzing Book*'s "Grammar Coverage" chapter gives the GrammarCoverageFuzzer that our tool follows. Inputs from Hell (TSE 2022) adds probabilistic control over which expansions are favored.

### Cited Findings (annotated bibliography)
- **Havrikov, N., Zeller, A.** (2019). "Systematically Covering Input Structure." *2019 34th IEEE/ACM Int. Conf. on Automated Software Engineering (ASE)*, pp. 189–199. DOI: 10.1109/ASE.2019.00027 [CR]. Its abstract says the "k-path algorithm for grammar production systematically covers syntactic elements as well as their combinations", giving "significantly higher code coverage than state of the art". It is the primary citation for k-path grammar coverage, which generalizes the expansion coverage our generator maximizes (k=1 is individual symbols, k=2 is symbols in the context of their parent). — [Crossref/DOI](https://doi.org/10.1109/ase.2019.00027); abstract via [CISPA record](https://publications.cispa.saarland/2971)
- **Havrikov, N., Kampmann, A., Zeller, A.** (2022). "From Input Coverage to Code Coverage: Systematically Covering Input Structure with k-Paths." *ACM Transactions on Software Engineering and Methodology (TOSEM)* [WS]. It defines k-path coverage formally (k=1 covers all symbols; k=2 covers all symbols in the context of all their parents). It shows that k-path coverage of inputs correlates with code coverage and can predict it, evaluated on JSON, CSV, URL and Markdown processors. This justifies using grammar coverage as a proxy adequacy measure when code coverage is unavailable, as with black-box chatbots. — [CISPA record](https://publications.cispa.de/articles/journal_contribution/From_Input_Coverage_to_Code_Coverage_Systematically_Covering_Input_Structure_with_k-Paths/24612432). **The DOI could not be verified** (Crossref search did not return it). Obtain it from the ACM DL before citing.
- **Zeller, A., Gopinath, R., Böhme, M., Fraser, G., Holler, C.** *The Fuzzing Book*, chapter "Grammar Coverage." CISPA Helmholtz Center for Information Security. URL: https://www.fuzzingbook.org/html/GrammarCoverageFuzzer.html [WS]. It introduces `GrammarCoverageFuzzer`, which extends `GrammarFuzzer` with the goal of covering all expansions at least once, preferring uncovered expansions, and it also discusses deeper (expansion-in-context) coverage. **This is the direct algorithmic basis of our prompt generator.** — [fuzzingbook.org chapter](https://www.fuzzingbook.org/html/GrammarCoverageFuzzer.html); [Part III: Syntactic Fuzzing](https://www.fuzzingbook.org/html/03_Syntactical_Fuzzing.html). The book provides a "How do I cite" section with a BibTeX entry (typically a `@book` with a retrieval date), but its text could not be retrieved. Copy it from the site and include the access date.
- **Soremekun, E., Pavese, E., Havrikov, N., Grunske, L., Zeller, A.** (2022). "Inputs From Hell: Learning Input Distributions for Grammar-Based Test Generation." *IEEE Transactions on Software Engineering* 48(4), 2022 (online 2020). DOI: 10.1109/TSE.2020.3013716 [CR]. It learns production probabilities from sample inputs to generate "common" inputs, or inverts them to generate "uncommon" ones. This provides a probabilistic counterpart to coverage-based expansion selection and a way to bias prompts toward typical or atypical phrasing. — [Crossref/DOI](https://doi.org/10.1109/tse.2020.3013716). The Crossref title field is truncated to "Inputs From Hell:". The subtitle is from memory and is consistent with the paper.
- **Lämmel & Schulte (2006)** and **Purdom (1972)** (see Q1) are the classic coverage-criteria precedents: production coverage, and combinatorial coverage under control. — [DOI](https://doi.org/10.1007/11754008_2); [DOI](https://doi.org/10.1007/bf01932308)

### Inferences
- Our tool implements k=1 expansion coverage in the style of The Fuzzing Book. Havrikov & Zeller give the natural extension (k≥2) and empirical evidence that input-structure coverage is meaningful when code coverage is unobservable, which is exactly the case for Hugging Face chatbots.
- A Related Work paragraph can place our tool as "the GrammarCoverageFuzzer strategy [Fuzzing Book], i.e. 1-path coverage [Havrikov & Zeller 2019], applied to a natural-language prompt grammar with a differential oracle [Csmith]."

## Q3. Is there any work applying grammar-based generation to natural-language prompts or LLM inputs?

### Takeaway
No peer-reviewed work was found that uses a **context-free grammar with grammar-coverage guidance** to generate natural-language prompts for differential testing of chatbots. The nearest neighbors fall into four groups: template- or DSL-based NLP and jailbreak generation (CheckList, h4rm3l), mutation-based LLM jailbreak fuzzers (GPTFuzzer, FuzzLLM), LLMs used *as* fuzzers (Fuzz4All, ChatAFL), and chatbot or dialogue testing with metamorphic or perturbation oracles (Bozic & Wotawa, Charm, DialTest). This gap supports our study's novelty, though it is an absence-of-evidence finding from a limited search.

### Cited Findings (annotated bibliography)

**Template / grammar-like generation of NL test inputs**
- **Ribeiro, M. T., Wu, T., Guestrin, C., Singh, S.** (2020). "Beyond Accuracy: Behavioral Testing of NLP Models with CheckList." *Proc. 58th Annual Meeting of the ACL (ACL 2020)*. DOI: 10.18653/v1/2020.acl-main.442 [CR]. It generates NLP test cases at scale from templates with fill-in lexicons and checks capabilities with invariance and directional tests. This is the closest NLP precedent for structured, template- or grammar-driven input generation with metamorphic-style oracles. — [Crossref/DOI](https://doi.org/10.18653/v1/2020.acl-main.442)
- **Doumbouya, M. K. B., Nandi, A., Poesia, G., et al. (incl. Jurafsky, D., Manning, C. D.)** (2025). "h4rm3l: A Language for Composable Jailbreak Attack Synthesis." *ICLR 2025*. arXiv:2408.04811 [WS]. It defines a DSL that expresses jailbreak attacks as compositions of parameterized prompt transformations, plus a bandit-based synthesizer. It reports 2,656 successful novel jailbreaks against 6 LLMs. This is the closest work using a *formal language* to generate LLM inputs, although it composes transformations rather than deriving sentences from a CFG. — [arXiv](https://arxiv.org/abs/2408.04811); [ICLR poster](https://iclr.cc/virtual/2025/poster/27663). **The full author list (8 authors) was not fully confirmed.** Copy it from the arXiv page. Cite only to disambiguate "grammar" in LLM security. — [arXiv HTML](https://arxiv.org/html/2503.24191v3). Authors were not verified.

### Inferences
- The literature splits into two groups that do not overlap: (a) grammar and grammar-coverage fuzzing of formal-language software, and (b) LLM and chatbot testing driven by templates, mutation or LLMs. Our study connects them: CFG plus expansion-coverage guidance (from group a) applied to NL prompts, with a cross-model differential oracle (Csmith-style), against Hugging Face chatbots (group b).
- CheckList, FuzzLLM and h4rm3l are the strongest "closest work" citations. Each uses fixed templates or a transformation DSL rather than a recursive CFG with coverage feedback.
