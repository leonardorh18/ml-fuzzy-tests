\section{Background and Related Work}\label{sec:related}

Our approach combines four lines of work that have developed largely in separate communities: grammar-based fuzzing, differential testing, metamorphic testing, and the testing of LLMs.

\subsection{Grammar-Based Fuzzing and Grammar Coverage}

Grammar-based generation dates back to Purdom's sentence generator for testing parsers \citep{purdom1972sentence}. Modern grammar-based fuzzers such as LangFuzz \citep{holler2012langfuzz}, Skyfire \citep{wang2017skyfire}, Nautilus \citep{aschermann2019nautilus}, Superion \citep{wang2019superion}, and Gramatron \citep{srivastava2021gramatron} derive syntactically valid inputs for interpreters and parsers and rely on crash or sanitizer oracles. Nautilus, the closest precedent for coverage-guided grammar fuzzing, is guided by code coverage. When code coverage is unavailable, coverage of the input grammar itself can serve as an adequacy criterion: \citet{havrikov2019kpath} formalized $k$-path coverage, and its journal extension showed that input-structure coverage correlates with code coverage \citep{havrikov2022kpath}. The \code{GrammarCoverageFuzzer} of \emph{The Fuzzing Book} \citep{zeller2024fuzzingbook} implements the 1-path variant by preferring uncovered expansions and is the direct basis of our generator. Probabilistic grammars offer an alternative way to steer generation \citep{soremekun2022inputs}.

All of these fuzzers target formal languages. None derives natural-language prompts, and none uses grammar coverage as the only feedback available against a black-box generative model.

\subsection{Differential Testing}

Differential testing runs one input through several systems that should behave alike and treats divergence as a failure \citep{mckeeman1998differential}, extending the earlier pseudo-oracle idea \citep{davis1981pseudo}. Csmith made it a standard method for compilers by generating only valid C programs, so that every disagreement is meaningful \citep{yang2011csmith}. Coverage guidance and differential oracles have been combined before, for example for JVM implementations \citep{chen2016jvm}. In machine learning, DeepXplore used disagreement among several deep networks as an oracle that needs no labels \citep{pei2017deepxplore}, and CRADLE compared deep-learning library backends \citep{pham2019cradle}. Recent LLM-related differential work mostly uses the LLM as a \emph{generator} of tests for other software, as in TitanFuzz \citep{deng2023titanfuzz}, rather than as the system under test.

Unlike compilers, chat LLMs share no formal specification, so a disagreement is only a signal. Work on hallucination detection uses cross-sample and cross-model consistency in a similar way \citep{manakul2023selfcheckgpt,zhang2023sac3}, but also warns that models can agree on a wrong answer \citep{zhang2023sac3}. Our verifiable prompts address both points: ground truth identifies which model is wrong and exposes cases where all models are wrong.

\subsection{The Test-Oracle Problem and Metamorphic Testing}

Free-form chatbots are ``non-testable'' programs in Weyuker's sense \citep{weyuker1982nontestable}: there is no practical way to specify the correct output for every input. \citet{barr2015oracle} survey solutions to this oracle problem. Metamorphic testing \citep{chen1998metamorphic} checks relations between the outputs of related inputs instead of individual outputs. In NLP, CheckList generates tests from templates and checks invariance under meaning-preserving changes \citep{ribeiro2020checklist}, and TransRepair found inconsistency bugs in machine translation without a human oracle \citep{sun2020transrepair}. Consistency under meaning-preserving rephrasing is poor in pretrained language models \citep{elazar2021consistency}, and single-prompt evaluation of LLMs is unreliable \citep{mizrahi2024multiprompt,errica2025sensitivity}. Metamorphic testing frameworks for LLMs have appeared at software-testing venues, including METAL \citep{hyun2024metal}, the large catalogue of metamorphic relations by \citet{cho2025metamorphic}, and MORTAR for multi-turn dialogue systems \citep{guo2026mortar}. Drowzee derives metamorphic test cases with known answers to detect factual hallucinations \citep{li2024drowzee}.

These frameworks compare a model against itself: a violated relation shows inconsistency but not which answer is wrong. Our paraphrase relation is a CheckList-style invariance test, but the same grammar derivation also provides the expected answer and is sent to several models. Self-consistency decoding \citep{wang2023selfconsistency} votes over sampled \emph{outputs} to improve accuracy, whereas we test invariance over paraphrased \emph{inputs} to find failures.

\subsection{Fuzzing and Testing LLMs and Chatbots}

Existing LLM fuzzers target security. GPTFuzzer mutates jailbreak templates \citep{yu2023gptfuzzer}, FuzzLLM composes jailbreak prompts from fixed parts \citep{yao2024fuzzllm}, and h4rm3l synthesizes attacks in a domain-specific language \citep{doumbouya2025h4rm3l}; their oracle is attack success. Earlier chatbot testing in software engineering addressed rule-based or recurrent dialogue systems \citep{bozic2019chatbots,liu2021dialtest}. \citet{wang2024survey} survey the broader use of LLMs in software testing.

The NLP literature documents the functional weaknesses our grammar targets. IFEval evaluates instructions that code can verify \citep{zhou2023ifeval}. Formatting changes alone can change accuracy by up to 76 points \citep{sclar2024formatting}. Models often fail at character-level manipulation such as spelling, counting, and reversal \citep{edman2024cute,chai2024tokenization}; under-trained tokens can break rare Unicode strings \citep{land2024magikarp}; and template-instantiated variants of math problems expose unstable reasoning \citep{mirzadeh2025gsmsymbolic}. These results come from static benchmarks, mostly on large models.

\subsection{Positioning}

To our knowledge, no prior work combines a context-free prompt grammar with grammar-coverage guidance, a cross-model differential oracle, and a cross-paraphrase metamorphic oracle for open chat models. Each ingredient has a canonical precedent: the \code{GrammarCoverageFuzzer} for generation, Csmith and DeepXplore for the differential oracle, and CheckList for the invariance oracle. Our contribution is to combine them, with the grammar derivation itself supplying the ground truth that settles disagreements.
