\section{Background and Related Work}\label{sec:related}

Our approach combines four lines of work that have developed largely in separate communities: grammar-based fuzzing, differential testing, metamorphic testing, and the testing of LLMs.

\subsection{Grammar-Based Fuzzing and Grammar Coverage}

Grammar-based fuzzers derive syntactically valid inputs from a grammar so that tests reach beyond the parser of the system under test. LangFuzz, a black-box fuzzer driven by a context-free grammar, found 105 severe vulnerabilities in Mozilla's JavaScript engine in three months \citep{holler2012langfuzz}. When the internals of the system cannot be observed, coverage of the input grammar itself can guide generation: \citet{havrikov2019kpath} formalized $k$-path coverage of a grammar, and the \code{GrammarCoverageFuzzer} of \emph{The Fuzzing Book} \citep{zeller2024fuzzingbook} prefers expansions not yet used, which corresponds to 1-path coverage and is the direct basis of our generator. Grammar-based fuzzers have targeted formal languages such as programming languages; we apply the same idea to natural-language prompts.

\subsection{Differential Testing}

Differential testing gives the same input to several systems that should behave alike and treats divergence as a failure \citep{mckeeman1998differential}. Csmith made it a standard method for compilers by generating only C programs without undefined behavior, so that every disagreement is meaningful; it found more than 325 previously unknown compiler bugs \citep{yang2011csmith}. DeepXplore brought the idea to machine learning, using several models with the same function as cross-referencing oracles that need no labels \citep{pei2017deepxplore}. Chat LLMs share no formal specification, so a disagreement among them is only a signal. Work on hallucination detection shows that cross-checking a model against other models catches errors that self-consistency misses, but also that models can be consistently wrong \citep{zhang2023sac3}. Our verifiable prompts address both points: ground truth identifies which model is wrong and exposes cases in which all models agree on a wrong answer.

\subsection{The Test-Oracle Problem and Metamorphic Testing}

Deciding whether an output is correct is the test-oracle problem \citep{barr2015oracle}, and free-form chatbots are an extreme case of it. Metamorphic testing \citep{chen1998metamorphic} sidesteps the problem by checking relations between the outputs of related inputs. In NLP, CheckList generates tests from templates and checks invariance under meaning-preserving changes \citep{ribeiro2020checklist}. For LLMs, METAL generates hundreds of metamorphic relations from templates to test quality attributes such as robustness \citep{hyun2024metal}; \citet{cho2025metamorphic} collected 191 metamorphic relations for NLP tasks and ran about 560 thousand metamorphic tests on three LLMs; and MORTAR extends metamorphic testing to multi-turn dialogue systems, revealing 51\% more bugs per test case than single-turn testing \citep{guo2026mortar}. These frameworks compare a model with itself: a violated relation shows inconsistency but not which answer is wrong. Our paraphrase relation is a CheckList-style invariance test, but each grammar derivation also carries its expected answer and is sent to several models.

\subsection{Fuzzing and Testing LLMs and Chatbots}

Most LLM fuzzing targets security. GPTFuzzer mutates jailbreak templates and reaches attack success rates above 90\% against ChatGPT and Llama-2 \citep{yu2023gptfuzzer}; its oracle is whether the attack succeeded. \citet{wang2024survey} review 102 studies on LLMs in software testing, nearly all of which use LLMs to test other software rather than test the LLMs themselves. Meanwhile, NLP research documents the functional weaknesses our grammar targets: formatting changes that preserve meaning can shift accuracy by up to 76 points \citep{sclar2024formatting}, and models that know how their tokens are spelled still fail to manipulate text at the character level \citep{edman2024cute}. These findings come from static benchmarks, mostly on large models.

\subsection{Positioning}

To our knowledge, no prior work combines a context-free prompt grammar with grammar-coverage guidance, a cross-model differential oracle, and a cross-paraphrase metamorphic oracle for open chat models. Each ingredient has a canonical precedent: the \code{GrammarCoverageFuzzer} for generation, Csmith and DeepXplore for the differential oracle, and CheckList for the invariance oracle. Our contribution is to combine them, with the grammar derivation itself supplying the ground truth that settles disagreements.
