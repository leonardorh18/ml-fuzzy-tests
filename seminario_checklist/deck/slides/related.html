Part 1: How does CheckList compare with previous work? Before CheckList, each approach covered only one piece of the problem. Accuracy on benchmarks gives only one number, so it doesn’t show where the model fails. Robustness and fairness tests, like adding typos or swapping names, look at one skill or one task at a time. Challenge sets are small and made by hand. And probes look inside the model, but not at how it behaves on the real task; for example, a probe shows BERT can recognize names, yet BERT fine-tuned on a real task still fails simple tests with names. CheckList brings these ideas together in one method, using ideas from software testing: unit tests and metamorphic tests. Now, to understand how it works, we need some key concepts.
