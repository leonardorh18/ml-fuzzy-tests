Part 1: How does CheckList compare with previous work? Before CheckList, each approach covered only one piece of the problem. Accuracy on benchmarks, like the SQuAD leaderboard of Rajpurkar and colleagues, gives only one number, so it doesn’t show where the model fails. Robustness and fairness tests look at one skill or one task at a time: for example, Belinkov and Bisk showed that noise and typos break translation models, and Prabhakaran and colleagues swapped names to detect bias. Challenge sets, like the stress tests for natural language inference by Naik and colleagues, are small and made by hand. And knowledge tests, also called probes, check what the model has learned internally. They show the model knows something, but not that it uses it. For example, Tenney and colleagues showed that BERT recognizes names with 96.7% accuracy, yet BERT fine-tuned on a real task still fails simple tests with names. CheckList brings these ideas together in one method, using ideas from software testing: unit tests and metamorphic tests. Now, to understand how it works, we need some key concepts.
